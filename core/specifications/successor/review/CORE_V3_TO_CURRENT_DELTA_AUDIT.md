## 1. 判定与适用范围

**建议采用出口 B：原 Core v3.0 保持冻结，另立独立的后继数学规范。** 原 v3 仍准确表达原 106 个 P-ID 的条件合同；它已包含大量必要反例、协议相对性、模型前提和不可外推边界。当前理论在它之后增加了可测与自适应预测来源、实际覆盖与训练部署联合风险、源导出的连续随机分析和谱工厂、同源生命周期连接、有限钱包决策、表示与机制后悔，以及付费再生和增长的参数分类。原 v3 单独使用已不足以完整表达这些现行成果，但本次审计没有发现必须重定义其 106 个 P-ID 才能表达新增成果的理由。

出口 A 不充分：只改善入口或引用书稿，不能为这些新增合同提供稳定的定义、量词、证明层次和下游适用条件。出口 C 目前不必要：现行差异可以由保留旧权威、增加相互独立且具来源的合同完成；重写完整旧规格会制造重复权威和不必要的兼容风险。

“独立后继规范”在本文中是**新增的规范性参考合同**，不表示所有新增内容都已成为新的 Lean 命题，也不表示它取代冻结源成为原 106 个端点的证明对象。当前数学书的出版版本为 **v4.1**，与 formal specification v3.0 是不同版本轴。

## 3. 判定用语

| 代码 | 判定 | 使用规则 |
|---|---|---|
| S | 原 v3 已足够 | 旧定义、命题或边界已经明确；保留原文本和原证明对象。 |
| R | 补充引用或说明 | 新材料给解释、来源对齐、既有工具的实例或出版澄清；不需要重立旧命题。 |
| A | 独立规范附录／后继合同 | 新对象、新量词、新来源工厂、强化结论或可执行消费者需要单独陈述。此为本轮 B 架构的主要新增内容。 |

| Δ | 明确的源、权限或评价变化 | 相对于先前具体源增加或改变环境、信息、资源、程序或时钟；必须作为新的条件合同，不能伪称旧源免费得到新结论。Δ 可以与 A 同时成立。 |

“加强了来源”与“加强了假设”不同：若从原始机制证明过去接口字段所要求的特征数据、漂移、真实记录律或资金界，新增的是来源定理；若增加传感器、供给或固定初态，则是新的模型前提。两者不能用一个“已统一”标签合并。

## 7. 最小充分规范的结构建议

独立后继规范宜有四层，并让每层直接链接当前源，不复制原 106 项正文。

1. **权威与定义层**：冻结 v3 SHA、106集合和证明目标不变；书籍版本与规范版本分开；声明“同一源、同一策略、同一记忆、同一资源、同一对象”各自的可检查意义。列预测、身体、身份、组织、评价、长期对象的类型，不把它们放入一个无类型同一性。
