# Core 后继规范：验证范围与复现

本轮是文档与映射升级，不修改生产 Lean 或三书。验证分为源码／文档静态完整性、真实来源证据复用、人工数学语义审查三个层次；它们不能互相替代。

## 运行方式

在仓库根目录运行：

```sh
python core/specifications/successor/validate_successor.py
```

脚本核对固定基线、允许修改范围、冻结 SHA/字节/106 锚点顺序、真实声明与公共 import、来源回执的当前字节身份、合同索引、双语的十二字段/公式/代码接口及所有新增 Markdown 本地链接。脚本明确不执行 Lean、lake、全量 CI 或书籍构建。

实际输出见 [机器回执](validation/STATIC_VALIDATION.json) 与 [可读回执](validation/STATIC_VALIDATION.md)。最终验收会在全部审查修改落字后再次执行同一命令；本文件的统计与最终机器回执应一起读取。不存在的声明、错文件、伪源 SHA 或虚构 import 边都不允许由猜测补齐。

## 检查能力的界限

源扫描是去除注释／字符串后的文本声明与 import 图解析，不是 Lean elaborator，也不重验编译后的 proof term。中英一致性检查核对 ID、字段顺序、公式原字符串和完整声明清单；自然语言的数学同义性由实际审读承担。逐卡审查、发现和处理见 [REVIEW.md](REVIEW.md)。

历史回执只在当前源码 SHA 与登记值吻合时复用；`compiled_in_this_document_upgrade` 保持 false。旧 106 的形式化状态继续由原账本和冻结源负责。本轮不宣称新增数学证明、经验验证或尚未发生的 GitHub 合并。
