## 3. 从原始理论到当前 QM 内核的对应

### 3.1 Being through Becoming：保留响应与合法演化的关系

原 PDF 把持续存在归于关系结构与持续生成。Core §0.1、§3–4 将这一方向改写为明确的过程、历史、因子和响应核；§7 进一步要求更新尊重等价类。Kernel 1 已把这一接口落实到密度态的全词响应商和正概率后验。新有限坐标层为这个商提供有限表示。

这里的对象身份是相对于声明未来和协议的响应身份。两块硬件、两个空间位置或者两份独立准备即使具有相同响应，也不能仅凭 hash 或响应等式认定为同一历史实例。Core §3.1、§3.3 已区分嵌入因子、抽象表示和物理载体；本轮的上下文指纹只标识确切模型与基。

### 3.2 Generic object、强持续对象和 Ω

PDF §2.2（p.4）以闭反馈和非零一阶同调提出强本体主张。Core §12.1 的 D-OBJ 则列出候选因子、声明未来、预测与动态闭合、因果接口、运输与范围记录；恢复、自维持、遗传和目的需要各自增加合同。`CORE_V3_POST_CORE_SCIENTIFIC_CLOSURE.md` §3.3 与开放端口矩阵 R0-02 明确保留这种区别。

因此，有限响应坐标在每一步仍能合法更新，支持的是一种操作闭合。它没有自动提供供能、自修复、环境扰动后的存活、非平凡吸引子或自创生组织的证据。完整 D-OBJ 的现实因果接口与历史运输也需要单独接入。

Core §12.2 的 Ω 是先冻结对象证书、时间域和移除语义，再从机制失效数据定义的极小毁损结构。其超图重建需要失败单调性。它不能直接由 \(W_*\) 的基数、一个量子电路回路或者测量结果数替代。当前 QM 表示证书不定义或认证物理 Ω 超图。

### 3.3 目的与双驱动

PDF §2.3 从 Π/Φ 叙述内在目的与最优方向。Core §18.3 保留同对象异目的反例，§23.2 保留目标分解的 gauge，自身存在不能指定唯一奖励；§27.3 区分信息价值与信息增益。三个 post-Core 文件把目的机制识别分别登记在 C6，并把共同二维机制的可失败检验登记在 C5。

本轮 \(x_j=\operatorname{tr}(\rho B_j)\) 是响应概率坐标；它既不是自动识别出的 Π/Φ，也不是两维驱动定理。Z/HZ/HSZ 的坐标数 2/3/4 描述不同协议的区分能力，包含一个恒定迹坐标。这个维数不是目标数量、Hilbert 维数、Shannon 熵或者决策收益。

若以后以该坐标规划量子控制，应另外给出奖励/损失、动作成本、时域与可实施策略，并证明相应奖励和动作条件在坐标纤维上保持。当前完整记录律足以支持后续的这项研究，但不会自行生成最优目标。

### 3.4 Ω、量子结构和三代的原始猜想

PDF §4.2.1（pp.30–31）提出由信息几何与闭相位推导非交换关系；§4.2.2（pp.32–33）把三代与 \(\beta_1=3\)、\(\operatorname{Index}(D)=\beta_1\) 联系。当前新定理没有使用这些等式作为隐含前提，也没有给它们新增机器证明。

Core §0 明确排除量子专属结构作为 generic 数学核心的基础。Kernel 1 的有限复矩阵、PSD 锥、Born 迹配对与 Kraus 操作是公开输入；三代选择沿指定完整谱及窗口合同推进。要恢复原始几何路线，必须明确给出空间、算子、表示/丛、谱机制及其关系，并证明相应桥，而不能将同为“三”认作恒等。

一个直接的有限维边界是：当 \(d>0\)、\(\hbar\ne0\)，有限矩阵满足

\[
\operatorname{tr}[Q,P]=0,
\qquad
\operatorname{tr}(i\hbar I_d)=i\hbar d\ne0.
\]

所以当前有限矩阵内核无法实现全空间上精确的 \([Q,P]=i\hbar I\)。连续变量、无界算子定义域或明确的截断误差，需要专门的 CV 桥。这个代数障碍限制模型类，不否定当前有限维量子信息和记录推导。

## 4. 为什么有限证书可以具有全部有限词的含义

固定有限操作库，每个动作每一步均可实施；词为按时间排列的动作—结果对 \(w\in(A\times O)^*\)。加权运行接口是

\[
\mathcal I_e(X)=\sum_k w_{ek}K_{ek}XK_{ek}^\dagger,
\qquad
\mathcal I_e^*(E)=\sum_k w_{ek}K_{ek}^\dagger E K_{ek}.
\]

规定

\[
E_{\varnothing}=I,
\qquad E_{e::w}=\mathcal I_e^*(E_w),
\qquad W_*=\operatorname{span}_{\mathbb R}\{E_w:w\text{ 有限}\}.
\]

证书提供 \(r\) 个实际词 \(w_j\)、矩阵 \(B_j=E_{w_j}\)，其中 \(B_0=I,w_0=\varnothing\)，以及每个允许分支的实系数矩阵 \(A_e\)，并逐项满足

\[
\mathcal I_e^*(B_j)=\sum_{k=0}^{r-1}(A_e)_{jk}B_k.
\]

令 \(V=\operatorname{span}_{\mathbb R}\{B_j\}\)。每个 \(B_j\) 来自实际词，故 \(V\subseteq W_*\)。另一方面，单位效应在 \(V\)，局部恒等式加线性性保证 \(V\) 对全部分支拉回闭合。按词长归纳得每个 \(E_w\in V\)，故 \(W_*\subseteq V\)。于是 \(V=W_*\)。

在此条件下，所有 \(B_j\) 的迹配对相等，当且仅当所有有限词的响应相等。分支更新遵守

\[
y=A_e x,\qquad p=y_0,\qquad x'=y/p\quad(p>0).
\]

有限证书的作用是检查生成和闭包这两个充分条件。只查看有限深度的部分响应相等，不能替代闭包：例如以 Z/H 库只保留 \(I\) 或 \(I,P_0\) 的未闭合方向，会在真实拉回等式处被拒绝。

线性独立性是运行证书额外验证的条件。它使 \(B_j\) 成为 \(W_*\) 的实基，令拉回系数唯一。这个最小性属于线性效应表示；任意非线性编码、更小的物理 Hilbert 实现、有限比特成本或更窄协议语言的最小性，均不是其推论。

## 5. 新 checker 的具体合同与可信范围

实现：[`representation_certificate.py`](../kernel/ueot_qm/representation_certificate.py)。

公开 API：

```python
certificate = export_representation_certificate(model)
receipt = verify_representation_certificate(
    certificate,
    expected_library=model.library,
    expected_context_fingerprint=model.fingerprint,
)
```

导出物是可以用 `json.dumps` 保存的普通 JSON 字典。核验不依赖导出时的 Python 对象存活；调用方提供期望的库作为外部上下文锚。可选的模型指纹还固定基身份。若未固定模型指纹，同一库下另一个正确的基可以合法通过，并得到自己的上下文指纹。

checker 实施下列独立检查：

| 合同 | 复查方法 | 能拒绝的错误 |
|---|---|---|
| JSON 精确模式 | 字段集合、类型、整数和约分后的正分母分数 | 额外主张、浮点、字符串、bool 冒充整数、非规范分数 |
| 库身份 | 从公开 action/outcome/Kraus 字段重建 payload 与 hash | 库替换、缺失或重复标签、字节表示错配 |
| 合法操作 | 重算每个动作的 \(\sum wK^\dagger K=I\) | 负权、错维数、完整性被篡改 |
| 单位起点与词 | 从 \(I\) 反向依次施加实际 Kraus 拉回 | 错词、颠倒时间顺序、未知动作、虚构效应 |
| 实基 | 检查 Hermitian 与 Frobenius Gram 行列式严格为正 | 依赖基或非 Hermitian 方向 |
| 全部分支闭包 | 对每个分支和每个基逐矩阵元比较 | 漏分支、重复分支、转置系数、错误系数、伪闭包 |
| 返回身份 | 对完整证书计算独立 hash，记录词数与局部等式数 | 回执与后来修改的 JSON 混用 |

checker 不调用 `PredictiveModel` 构造算法、不调用其高斯系数求解器，也不调用 `Instrument.adjoint`。它使用公开的精确 Matrix/Kraus 表示，直接计算 \(\sum wK^\dagger B_jK\) 和证书声明的线性组合；独立性通过实 Frobenius Gram 行列式检查。精确矩阵乘法、迹、行列式和 Python 整数/Fraction 运算仍属于可执行可信底座，本轮没有把它们的实现反射进 Lean。

### 资源合同

当前实现支持 Hilbert 维数 \(1\le d\le4\)，\(1\le r\le d^2\)。每个导出词见证的长度最多 \(d^2-1\)，所以最大为 15；全部 \(r\) 个见证最多共 240 个字母。生成器的每个新增基来自更早的一个基，因此确实能给出这种长度的见证。checker 会明确拒绝超长见证，即使长词在数学上等价于一个短词。

这里限制的是证据大小，并不限制证书所覆盖的未来词长。动作、结果、Kraus 项使用已声明有限库；复查成本随该库的总项数和精确整数位数增长。本实现没有承诺对无限动作库、大维数或者任意位复杂度都提供统一资源保证。

指纹有意依赖具体 Kraus 表示。两份 Kraus 分解即使定义同一通道，也可能具有不同指纹；这是精确运行上下文身份，不是物理通道的完备不变量。

## 7. 动态信息与协议范围

本轮保存的是随记录更新的、对允许未来充分的响应坐标。它体现 Core §4.5 的递归信息结构，而非把一个固定标签永久当作对象状态。若环境相关性会影响未来，必须把相关记忆纳入联合模型，或者给出可验证的重置/无记忆合同；Kernel 1 已保留相同系统和环境边缘态却有不同未来的反例。

测量获得记录，同时改变量子状态。响应坐标的递归性不意味着熵在每一步下降、互信息单调增加、内核自己学习新的操作或自动获得目标。Core §5 的信息率失真需要指定输入分布与信息量；§27 的信念更新、模型误指定和决策价值有各自的模型及成本前提。这些量不能由 \(r\) 或某个后验概率直接替代。

覆盖范围必须同时保留以下区别：

- **本证书的全词性**：固定时齐库里任意有限词，来自精确局部矩阵恒等式。
- **完整有限因果树**：每条路径是允许词，动作只能依赖已有结果，全部结果枝必须显式存在；全词等式可接入其记录比较。
- **有限实验比较**：Kernel 1 的 `compare_finite_protocols` 只覆盖所列准备与树，有限比较得到 0 不自动成为本证书的全词等式。
- **更大或不同语言**：增加新操作、时间层约束、漂移、控制自动机、环境接口或无限时域性质时，需要重新给出模型和桥。

因此，本轮对应 C1/C7 中一个有限模型表示与复现切片，并为后续 C2 的数据识别提供明确的模型目标。它没有关闭 C1 的一般可测更新问题、C2 的现实对象与协议发现、C5 的共同驱动识别或 C7 的现实实验闭环。

## 8. 已执行验收与负对照

测试文件：[`test_representation_certificate.py`](../kernel/tests/test_representation_certificate.py)。

实际执行记录：新增 18 项测试方法通过，0.143 秒；随后与原有 `test_kernel.py` 合并复跑，50 项通过，0.597 秒。这是本角色的本地测试结果；最终合并后 CI 与统一回执另由主执行者记录。

关键正例包括手写的 Z 基 \(I,P_0\)、Z/HZ/HSZ 的 2/3/4 维表示、包含不可能结果的完整操作、维数 1 和 4 的例子。同一 HZ 模型合法交换两条非恒定基并同步更换系数，checker 可在新基指纹下通过；绑定原模型指纹时拒绝。这说明 checker 检查代数证据，而不是要求复制生产器唯一输出。

关键负对照包括：

- 故意禁止调用 `PredictiveModel`、两个 `linear_coordinates` 入口及两层 `adjoint` 方法，手写 Z 证书仍通过。
- 给错误的生成方向或不闭合子空间重算一个自洽的 hash，checker 仍因实际词/闭包等式失败而拒绝。
- 重复真词制造线性依赖、颠倒 H→Z 的词顺序、转置拉回矩阵，分别触发相应数学条件失败。
- 不可能结果的拉回也必须为零，不能跳过或随意填充。
- 库内容和上下文 hash、非规范分数、bool/浮点、未知标签、重复/缺失分支、超出维数和证据长度合同，均被拒绝。

这些测试为指定实现提供可复查的正负证据。它们没有替代量子领域实验、通用数学证明或 Lean 的实际编译。

## 9. 本轮后可直接推进的精确缺口

1. **反射与适配**：连接 JSON 中的有理复数、加权 Kraus 和有限结果索引到 Lean 的 `FiniteObservablePresentation`，使特定证书产生可机器核查的数学实例。
2. **物理像与表示成本**：在明确需要外部坐标导入时再建立可实现性判定；箱约束 \(x_0=1,0\le x_j\le1\) 本身不足以判定存在密度态。有限维数也不等于有限精度的信息成本。
3. **协议扩展与误差**：对一个具体非时齐/有记忆模型，或者一个声明清楚的 operational 距离，证明额外的更新与误差桥。保持同一准备、协议和观测对应。
4. **物理来源**：三代继续接实际完整谱和有效窗口；Ω/拓扑、量子重构与连续变量各自给出可失败的明确桥，不通过复用符号宣布统一完成。

科学与工程状态由本轮主线验收汇总；本审查的 CLEAR 限于以上已读取来源、局部数学合同与已执行程序检查。
