# UEOT Theory Completion Roadmap v2：详细执行任务书

版本：1.0｜日期：2026-10-07｜第一轮窗口：2026-10-07—2026-12-29

科学依据：《CORE_V3_POST_CORE_SCIENTIFIC_CLOSURE.md》。工作包定义和 106 项对照：《CORE_V3_OPEN_PORT_MATRIX.md》。三份文档共同使用，均是新增规划资料；不是已执行研究成果清单。

## 1. 决策与目标

保留 Core v3、106 项证明、四项 counted generator 和现有 post-Core 成果。v1 作为历史合同保留；v2 将 generic Core 后续问题与强自维持/生命式组织支线分开，将“对象和评价桥汇合”替代容易误读的 Object→Purpose 单线图。

第一轮不是十二周证明七个全部开放问题。第一轮要交付：可靠的权威清单；P2 严格终审；一个相关数据有限发现/认证闭环；一个受限结构的载体算法；一个 Π/Φ 共同维数的可失败检验设计；一个非平稳运输小接口；一个目的机制试点设计；现实数据可用时至少一条独立验证链。C1 首轮主要交付明确的缺口和一个可启动定理题，不承诺一般状态全部形式化。

所有任务当前状态为 **PLANNED**；本次已经完成的是审计复核、有限反例验证和任务文档。后续源码、现实采集和仓库治理操作另按现行任务授权执行。

## 2. 总体依赖与推进规则

```text
R0 权威/语义/状态对账 ─┬─ C1 具体可测缺口
                     ├─ C2 数据与发现 ── C3 噪声载体 oracle
                     ├─ C4 身份/GOA 运输 ← C2 漂移误差
                     ├─ C5 共同维数检验 ← C2 误差与采样规则
                     └─ C6 机制桥 ── 合同表示/忠实性/viability 分别接 P2
C7 从 R0 起贯穿全部线：预注册、估计、负对照、复现、失败归因

独立支线：P5/P6 →（有机制需求再启）构造/谱系/自创生
```

不得跨过四个门：先确定数学目标；再冻结测量/协议；再做形式化或采集；最后按预注册标准判定。没有数据的任务可以完成方法论和模拟基准，不能填上“现实支持”。没有模型适配的通用结构不能宣布某个现实对象成立。

研究读取可以覆盖多线；单个主执行者每次只推进一个需要修改代码的科学包。跨 track 消费合并后的 canonical main，不消费别人未合并分支来抢进度。等待 CI 时做源/API/文档核对；避免修改同一公共根文件造成冲突。

## 3. 人力和时间假设

默认一位主执行者负责数学、实现和记录，另有独立审查角色在关键门提供 review。这里是角色安排，不假设已经分配某个人或启动代理。

十二周约 60 个正常工作日。工作包的全部增强版合计明显超过这一容量，因此第一轮只取最小科学切片，其他题进入下一轮。周末是休息/故障缓冲，不安排连续十四天工作。现实采集等待、独立审查排队和 CI 排队是外部时延，不通过压缩审查门掩盖。

## 7. 两个正式评审门

### G1：第二周范围冻结（10-20）

必须回答：真实输入是否可用？哪些协议可干预？候选族是否固定？相关误差如何估计？哪些目标只能做模拟？任务是否重复已有 theorem？第一轮 60 工作日预算是否够？

允许缩范围：C2 先分轮冻结而非任意 adaptive；C3 先一个结构特例；C5 先可信必要条件和功效；C6 先单机制。不得缩去独立认证、负对照、公共导出或错误预算。

### G2：第十二周终审（12-29）

每条 lane 交结论表：所完成的包；正向结果；拒绝/no-go；未决项；代码/数据/证明确切版本；机器状态；现实支持范围；下一轮唯一优先问题。重复引用已合并表面，不再开一份平行 Core coverage。

若有源码修改，按照现行治理给出 exact-head 和 resulting-main 验证；若只有数学研究或试验，则标明未形式化部分。所有 “关闭” 指向具体任务合同，不以阶段名称掩盖 stronger claim 未完成。

## 8. 风险、触发器和处置

| 风险/触发器 | 后果 | 预定动作 |
|---|---|---|
| 旧状态与当前 main 混合 | 错报完成或重开已绿项 | 更新 manifest；保留 historical 标记 |
| Core 与 public 源字节不一致 | 复现无法复指 | 比较哈希和版本；单独处理源同步 |
| 未知 gap 过小/样本覆盖不足 | 不能精确发现 | 输出未决区间、调整采样，不改成功标准 |
| adaptive 试验改变动力学 | 固定 mixing 假设失效 | 分轮冻结/重置；另列在线模型假设 |
| carrier 输出指数大 | 通用枚举无法提速 | 改 output-sensitive 或结构特例；记录漏检风险 |
| 物理删除非单调 | blocker 解释失效 | 改协议、保留响应表，不宣称因果完整性 |
| κ₁ 裕量趋零/时变太快 | GOA 运输或跟踪失证 | 停止远期外推，发布有限期或分岔边界 |
| C5 预算方向不足/误差过大 | 检验无功效 | 结果为不确定；增加测量，不能“不拒绝即支持” |
| 低秩但无 Π/Φ 锚 | 机制解释未识别 | 只报告局部有效维数 |
| 多个目的桥行为等价 | 唯一目的不可识别 | 输出等价类和新干预区分条件 |
| C7 无实际数据/干预权限 | 现实闭环不能验收 | 方法基准交付，现实支持 UNVERIFIED |
| Lean 底座缺失 | 扩展工期激增 | 复用明确 adapter；只补必要分析 lemma，不建全套库 |
| 审查/CI 排队 | 远程关闭延后 | 保持 REVIEW/REMOTE_PENDING，做不冲突的阅读 |

## 11. 下一轮如何选择

先按首轮证据重排，不继续顺着 P7–P12 编号惯性推进：

1. 若 C2 有可靠数据但泛化缺口大，下一轮优先 adaptive 采样/漂移与覆盖证明。
2. 若 C3 结构特例有明显收益，扩大到一个真实结构族，仍保持 output-sensitive 边界。
3. 若 C5 拒绝二维，增加 drive dimension 并研究机制来源；若不确定，先提高功效；若有限支持二维，继续独立锚定和域外预测。
4. 若 C6 已有可检验机制，强化桥的识别和反事实预测，而不是再造通用目的定义。
5. 若 C1 的具体更新/非紧题确实阻塞应用，激活其证明和必要 Lean 支撑。
6. 若真实系统明确需要生长、繁殖或资源路径保证，再从 P5/P6 启动强对象支线；不把它提升为 generic Core 完成标准。

选择准则是“它会减少哪一个已记录的不确定性、增加哪一个可独立验证的新预测”，而不是 theorem 数量或阶段编号。
