# 支持生存、可执行检查与注册联合风险闭合 V1

**结论：九个最终模块的本地构建、完整 `lake build UEOT`、两次一致的 Lean 原生导出及独立证明复核均已通过。** 本文记录给定源码和模型下的数学闭合。不可变 Git 候选、真实主分支授权和远端发布分别记录；本地通过不代表这些后续步骤已经完成。

本轮承接 [Deployment Joint Closure V1](./DEPLOYMENT_JOINT_CLOSURE_V1.md)，进一步把实际部署覆盖从外加数值前提连接到支持可行性，并允许校准良事件之外的记录不满足部署预算。冻结的 106 个 P-ID、四生成元、11 个生成结果、89 个适配项及六个边界均不改变；本增量未计入这些冻结账本。

## 1. 同一个实际过程上的支持充要条件

固定微观初态 PMF、观察映射、受控转移 PMF、认证谓词和有限时域。`FiniteSupportViability` 先给出不依赖待选策略的 `traceSupport` 递推，再证明：在当前策略实际赋予正概率的观察历史上，它等于该策略的真实末态后验支持。后验不是可以在换策略后保持不变的训练近似。

`zero_uncovered_iff_support_certified` 进一步刻画实际状态／动作行分布：未认证行的概率为零，当且仅当实际正历史中每一个受支持动作对整个相应支持集都被认证。这里使用的行分布与微观源、历史投影和策略来自同一构造。

在支持集合上定义后向递推：终点成立；一步成立要求存在一个当前动作，它认证当前所有可能微观状态，并使每个非空后继观察支持仍然可行。对**所有非空初始观察支持同时成立**的条件，有终端定理

`SupportViabilityClosure.initial_viability_iff_exists_zero_uncovered_policy`：

> 所有非空初始观察支持在给定时域可行，当且仅当存在同一个完整因果历史策略，使每一步的实际未认证行占据概率为零。

正向构造 `viablePolicy`，反向从实际零占据策略的正概率动作和历史支持归纳得到可行性。完整后备策略是显式输入，保证时域之外和未要求可行的历史上仍定义了策略；这也避免暗中假定动作类型非空。这个一般支持定理不要求观察类型 `Y` 有限。

零未认证行占据只说明执行过程停留在已认证的转移行。它不等于微观失效概率为零，更不等于无限时域生存。认证行仍可带有非零失效风险，后者由参考风险与传输误差预算处理。

## 2. 真正可执行的有限检查及反例

`FiniteSupportViabilityCheck` 提供有限关系表上的布尔递推。关系表必须通过

`R n x a z ↔ z ∈ (P n x a).support`

与实际 PMF 支持对接；正确性定理先连接关系表检查和 PMF 支持检查，再连接后向 `Viable` 命题。没有用不可计算的任意 PMF 支持查询冒充执行算法。有限状态和动作、可判定关系与认证谓词等条件仍是实际输入。

`ControlCoverageWitness` 包含三组不同的边界：

- 每个微观状态各自存在认证动作，不推出同一观察纤维有共同动作；只检查一个代表状态也不能控制实际未认证占据。
- 两条有正概率的观察历史可以共享同一个当前观察，却拥有不同的实际后验支持；逐历史支持认证可严格弱于全当前纤维认证。零概率历史不获得伪造的条件概率义务。
- 一个问题可以存在完整零未认证占据策略，同时存在一个已认证的可达前缀，执行它之后进入无法继续认证的死路。因此，“存在好策略”不能替换成“每个局部认证前缀均可延伸”。

最后一个有限例子的实际检查输出为 `(true, false, true)`。闭合没有把强的所有前缀可延伸条件当作必要条件，也没有为了证明存在性删除反例路径。

## 3. 固定注册实验与 Good-only 联合风险

`RegisteredDeploymentRisk` 使用同一个注册行集合和真实采样实验构造规范校准良事件。样本只存在于注册行；其真实边缘律、可测性、每行内部独立性和正样本数是前提。校准失败预算来自一次注册行并界，不在选择候选之后重复计算。

训练记录通过选择器确定候选，随后从该候选指定的实际微观部署律生成未来历史。联合概率因此使用既有 `selectedTrainingDeployment` 构造及其质量公式和塔式定理。经验拟合、实际覆盖上界和参考预算只需在同一个校准良事件上成立。

若良事件失败概率至多为 `α`，且良事件上同一所选过程的失效概率至多为 `β ∈ [0,1]`，则

\[
\Pr_{\mathrm{training, deployment}}(E)
\le \min\{1,\alpha+(1-\alpha)\beta\}.
\]

当前注册终端使用统一的 `Fin N` 样本数；一般的逐行 `N_j` 是另一个数学推广。当前事件包络 `henvelope` 仍要求所有候选满足。不能因为拟合、覆盖及预算已弱化为 Good-only，就把事件包络也误称为已经弱化。现行路径 TV／微观风险接口仍要求有限观察类型；一般支持定理的较宽范围不自动消除这一条件。

## 4. 用同一个生成策略消除覆盖输入

`ViableRegisteredJoint` 令所选候选实际部署 `viableFamilyPolicy`。在校准良事件上，初始支持可行性通过已经证明的 `viablePolicy_zero_uncovered` 给出该策略自己的零未认证占据，再直接进入注册联合风险终端。

因此，该组合接口不再外部假设所求实际覆盖上界。它仍要求良事件上的初始可行性、经验拟合及参考风险预算，以及通用测度、注册采样和事件包络等前提。将任意另一个策略的占据证书传给这里不满足这个同源契约。

## 5. 一个实际数据依赖选择例子

`RegisteredDeploymentRiskWitness` 独立构造两条注册源行，每行 256 个真实样本。两种动作的实际失效概率分别为 `1/8` 和 `1/4`；训练数据以 `7/8` 和 `1/8` 的概率选中它们，部署律确实随数据改变。

取校准半径 `1/8`，并界为 `16 exp(-8) ≤ 1/16`，经验拟合与覆盖的额外预算均为零。良事件上的参考风险至多 `3/8`；采用检查阈值 `β = 1/2`，通用联合证书给出 `17/32 < 1`。同一完全指定有限模型的实际联合失效概率还可精确计算为

\[
\frac78\frac18+\frac18\frac14=\frac9{64}.
\]

全一训练记录具有正概率，但它的经验检查预算为 1，因而不满足 `1/2` 阈值。这是不能要求所有训练记录通过预算的具体反例，不影响只要求良事件的定理。

这个数值例子直接证明自己的实际零占据并调用注册 Good-only 定理。它没有被宣称等于 `Classical.choose` 构造的支持生存策略；上一节的通用薄适配器是另一条已经证明的组合路线。`9/64` 是模型内精确概率，`17/32` 是保守保证，二者都不是外部实测结果。
