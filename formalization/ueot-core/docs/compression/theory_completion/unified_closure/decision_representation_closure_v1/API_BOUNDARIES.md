# 紧凑决策返回接口、认证范围与边界

本说明绑定本次实际编译及运行的 `FiniteJointDecisionDAG.lean`、`FiniteJointDecisionDAGGenerator.lean`、`RegisterDecisionRepresentation.lean` 与 `RETURN_REPRESENTATION_DAG.lean`。源 SHA、八个边界产物的 SHA 和针对性复核结果见 `representation_boundary_output_review.json`。它描述已完成的接口范围；没有增加新的验收门。

## 1. 公开输入和实际返回类型

公开入口是 `RegisterDecisionRepresentation.returned P prior hn ht initial H`。输入包含有限 θ 类型、非负且总和为 1 的有理先验、各 θ 的正常概率、公开 goal、正写入单价 c、非负价格系数 λ、0≤d≤1、非负初始钱包 B₀ 及有限总期限 H。菜单、评价和零终端继续使用原合同。θ 在整个过程开始时抽一次。

返回类型是 `Option (Result P prior hn ht initial H)`。`some result` 包含同一实际图、其有效根索引、全动作认证及实际所有行的源特定数量界检查。`none` 明确表示拒绝候选；拒绝结果不携带最优性结论。程序不会将失败替换为未经认证的候选策略。

内部 `Stat` 是自身请求与已交付收据的可计算摘要：elapsed、信息性正常/故障计数 s/f、实际付费次数 k，以及由许可历史重建的 root/child1 物理位、child1 存在、stopped 和首次分配相位。真正键为 `(remaining, Stat)`，公开输入由本次 `Model` 闭包绑定。每次 `generate` 都创建空 memo，不把别的先验、钱包、目标、价格或期限的缓存拿来使用。

`Local` 的物理位来自已证正确的 receipt 更新程序。生成器及控制器不会读取真实 Store、θ、隐藏 label、受保护程序或父身份。原生执行器继续保存那些完整世界数据。

## 2. 采用的证明路线：接受后正确

本次采用 Lean 候选生成器加已证明的精确 Lean 检查器。原四步全树入口曾实际运行 1713.890130 秒，旧序列化还要求四叉树输出；这些具体成本支持改为直接生成并执行共享图。实际入口不求值旧 `solve`、`fastSolve` 或证明用 `denote`。

`generate` 使用跨分支 `Std.HashMap (Nat × Stat) Nat`，子节点先于父节点完成；不同历史得到相同键时，返回同一数组索引。`Node.next` 保存已经生成的有限动作/收据/索引表。`certify` 不信任 memo、生成器报告的值或索引，而对候选数组重新检查：

1. 数组位置到 `(remaining,state)` 的键映射是单射。
2. 终端行的值为 0。
3. 每个非终端行对原菜单中的每一个合法动作、每个严格正概率收据，都有范围内的后继索引；后继的 remaining 恰少 1，state 恰为原模型 `next`。
4. 所选请求恰为原有理 `chooseBest` 在原菜单顺序上的结果，值恰为该请求完整奖费和折扣后继值之和。平局保留原先出现的动作。
5. 根索引有效，根状态恰为本次初始摘要，根 remaining 恰为 H。

源公共接口 `accept` 还对该同一数组运行 `boundCheck H`。这一步不只检查执行会用到的节点。

**已证明的是任意通过认证的图正确。未另行证明的是任意一般 Model、Hashable 实现和观察枚举下的 `generate` 必定通过认证。** 观察枚举只控制候选构造；检查器独立量化原 `Fintype O`，缺失正概率边会被拒绝。本次 Register 入口明确枚举全部四个收据；13 个登记实例均已实际返回 `some`。这些实例成功不是“任意 H 必成功”的证明。

`Certified` 的正确性也不依赖“生成器声称所有节点都从根可达”。它允许附带其它已认证、键不重复的有效节点；本次实际图的全动作根可达性由产物复核另外确认。源数量界覆盖整个已接受数组，包括任何附带行。

## 3. 最优性证明图和实际执行图

完整数组是最优性证明图：所有合法替代动作的正概率分支都在认证范围内。只取每个节点的 `choice` 边得到实际策略执行图。两者的节点和边数量须分别报告；不能用一条执行轨迹或仅选中请求的评分证明全动作最优性。

`node_value_eq_optimal` 以 remaining 归纳，利用全动作后继闭包，将每一行的报告值证明为旧模型的 `optimalValue`。`node_choice_eq_chosen` 还保持旧平局顺序。`denote_value_eq_node` 和 `certified_policy_value` 证明选中策略达到该报告值。`denote` 仅用于数学解释，没有进入实际生成、直接执行或 JSON 输出。

原生桥将这些结论接到同一个真实交易源。`result_native_value` 等同的是真实 once-drawn θ、原生完整 Store 运行的期望 J 与该根行报告值。`result_native_optimal` 的比较类仍是原允许信息、原菜单和钱包下的全部全历史实随机策略；对手只须在正概率实际前缀合法。对手不需要使用本次摘要、DAG 的内部记忆或其选中边。

`packedRun` 和 `nativeRun` 每步直接读当前节点、执行原交易、取得交付收据、更新摘要和游标，再进入下一时刻。它们不先构造树。`graph_native_payment` 与 `initial_graph_native_payment` 对实际正质量 primitive 路径给出每个前缀的请求预付与原记录实际费用账本，余额等于 `B₀ − k c`；不是期望预算约束。

## 4. 离轨默认值的精确含义

`controllerAction` 遇到不存在或越界的游标、state/remaining 不匹配、或当前菜单不允许的存储请求时，选当前菜单中平局优先的安全请求。Register 原菜单以 stop 开头且永远含 stop，所以本族默认请求为 stop。`controllerNext` 只沿严格正概率的收据边前进；零概率收据、失配请求或坏游标返回 `none`。

`controllerAction_mem` 对任意图、摘要、时刻和游标成立；`denote_feasible` 覆盖全部分支，包含零概率分支。源钱包适配与 `graph_native_payment` 再保证实际支持路径的逐前缀资金安全。因此安全默认值已经由一般定理覆盖，无需为坏索引增加另一个规划系统。

零概率历史的摘要更新仍是总函数，钱包可使用 `max 0`，计数后验在分母为 0 时回到原先验。这些是离轨定义，不声称不可能历史存在真实条件分布。在正质量原历史上，`positive_update` 证明分母严格正，源桥证明逐前缀扣账无需截断。

stop 的实际有效动作继续为 root idle，后续世界、故障、出生、append 和时钟照常推进。请求层预付 cap 仍按原请求计算：即使已 stopped，原写请求也不因其实际变为 idle 就获得免费的菜单许可。实际费用则按原交易记录计入。

缺失 child1 的请求和损坏槽 idle 的 `(0,0)` 不提供正常/故障证据。`uninformative_receipt`、`uninformative_increments` 和 `likelihood_counts` 已覆盖这两类；它们的本步似然为 1，而不是一份虚假的故障样本。`fresh` 只在第一次 append 可分配 child1；随后 None 槽不因尾部出生自动补齐。

## 5. 八个实际边界输出

所有下表实例使用同一冻结 driver `4b3537ff018ff234760dd1833ccacb7d0a0ccea392833b59730bf338e6d5763a`，实际执行均 exit 0，`bellman=true` 且 `node_bounds=true`。表中节点包括终端行，边包括所有合法替代动作的正概率边。

| 登记输入 | 精确根值 | 节点 / 边 | 实际解释 |
|---|---:|---:|---|
| H=0 | 0 | 1 / 0 | 存储的终端默认 action 不被执行；无请求、无收据、无 tick，原 founder 与 stopped=false 保持初态。 |
| B₀=0，H=3 | 0 | 7 / 15 | 所有非终端菜单恰为 stop/root idle/child1 idle；无实际写费，信息计数均为 0。 |
| B₀=3/4<c=1，H=3 | 0 | 7 / 15 | 请求前排除全部写入；不会用“未来也许免费失败”绕过预付。 |
| rθ=0，H=3，B₀=2 | 0 | 16 / 63 | 有余额时原写请求仍合法，但实际全故障、全零收费与出生；所有正收据边为 `(0,0)`、概率 1。 |
| rθ=1，H=3，B₀=2 | 81/80 | 39 / 99 | 实际请求为正确修复、stop、stop，收据为 `(1,1),(1,0),(1,0)`；stop 后仍连续出生。 |
| 低 r 先验为 0，高 r=3/4，H=3 | 2817/5120 | 52 / 127 | 正先验审计轨迹只有 θ=1；零权 θ 不会在过滤中复活。 |
| 两 θ 的 r 都为 1/2，H=3 | 123/640 | 52 / 127 | 计数可变化，但不能区分相同机制率的 θ 标签；正边概率仍为 1 或 1/2。 |
| 公开 goal=false，H=3 | 693/2560 | 52 / 127 | 初始坏位为 true，返回首请求 `root_write_false`；实际审计保留 false 健康后代和 None 槽。 |

针对性复核读取这些已有产物，没有重新求解。复核覆盖产物 SHA、全部行的键唯一性与时间/计数域、原请求预付菜单、正边总质量、索引递减、实际收费计数、精确 Q 递归和旧平局次序，并核对表中边界特征。最优性的源级依据仍是 Lean 已证检查器和原生桥。

五个主例另有既有 Python 完整 Store/memo 参考及独立原生检查。八个边界的范围是本次 Lean 已证检查器、直接 packed 执行和针对性产物复核；特别是 goal=false **没有**冒称通过原 Python goal=true 适配器的独立原生核验。

## 6. 数量界、序列化和计算成本的限度

`result_node_bound` 对返回数组本身给出

\[
|G|\le 24(H+1)^4.
\]

四个有限坐标是 elapsed、s、f、paidCount；remaining 由 `remaining+elapsed=H` 导出，Local 有 24 个保守可能值。该界不要求此表示全局最小，也不是有理数字节数、检查器时间或总内存的同阶复杂度证明。相同后验但不同计数的状态仍可分别保存。

预登记 H=8、B₀=2、c=1 的实际输出为 1,661 行、8,221 条证明边、根值 `884450457/1342177280`。单次记录为生成 852 ms、认证 1,740 ms、边界检查 1 ms、直接审计运行 1 ms、JSON 材料构造 931 ms，总入口 7.250239291 秒；编码及进程资源另由 stderr 和 RUN 记录。既有 Python memo 强基线已解出同值，不能把它描写成无缓存树求解器。纯生成、认证、序列化及整个入口的成本应分别解释，不作无依据的固定提速倍数宣传。

THIS driver 认证后直接执行同一内存数组和根，再序列化它们；没有把外部 Python 候选代入 Lean 的返回值。导出字节由实际 SHA 和独立产物检查绑定。本次没有新增 Lean JSON 反序列化器或往返定理，因而任意修改过的 JSON 不会自动获得内核证明。

所有结论仍限定于本轮原 root0/child1 权限、公开 goal、固定源族、固定评价、有限期限和外层控制器。地址2 的已证反例说明扩大未来权限可能要求更细表示；它没有被偷偷加入主菜单。外层电脑的实测成本也没有被算作原对象内部已闭环的认知能耗。
