## 1. Typing rule

A hierarchy row is identified by its actual mathematical relation, not by words
such as "level", "scale", "parent", "macro", or "long-run".

1. frozen P-ID surface;
2. canonical Lean theorem surface;
3. relation domain/codomain;
4. assumptions/certificates;
5. architecture role;
6. authority/provenance;
7. current lifecycle/disposition;
8. H1 coverage preparation.

The family-level architecture role is descriptive. G3 is cross-cutting and may
coexist with a G1/G2 construction in the same scientific family.

## 5. H0 separation findings

The inventory itself already blocks several false identifications:

1. **Resolution != quotient.** P-RES uses closure systems, minimal families,
   blocker duality and a lower/upper realization interval; M-QD by itself is a
   fibre-descent universal property.
2. **Cross-scale dynamics != parent formation.** P-DYN-04 transports one
   already-defined dynamics through scale maps. It does not construct a parent
   predictive object from several children.
3. **G2 assembly != H2 parent-object residual.**
   `agency_god_goa_from_history` assembles control and long-run semantics on one
   supplied state representation. It does not discharge P-COMP-01..07.
4. **Value hierarchy != object hierarchy.** P-ALI and merged teleological
   equivalence constrain values/directions/orderings after the relevant objects
   and objectives are supplied.
5. **Selection unit != parent object.** P-BRG-02 states what a declared
   response-to-replication bridge cannot distinguish; it does not establish
   objecthood.
6. **GOA != object formation.** P-GOA starts from an already supplied dynamics
   and studies invariant/long-run behavior.

These are H0 typing consequences, not yet the formal H3 no-go theorem set.
