# Track H — Hierarchy / Assembly Audit Mission

Status: **ACTIVE RESEARCH / POST-FINAL / UNCOUNTED**

Parent authority: GitHub Issue **#146**  
Governance: ../POST_FINAL_RESEARCH_GOVERNANCE.md

## Mission

Determine whether the hierarchy structures already present in frozen UEOT Core
v3 and the integrated post-FINAL theorem surface admit a smaller common
generating architecture, with special attention to genuine multi-input
parent-object assembly.

The mission does **not** assume that one universal hierarchy operator exists.

## Initial research surface

Primary frozen families:

- P-DYN-* — same-process cross-scale dynamics;
- P-RES-* — resolution and realization transport;
- P-COMP-* — composition and parent-object formation;
- P-ALI-* — multi-level value/alignment;
- P-BRG-* — object/selection bridge boundaries;
- P-GOA-* — only for classification/import inventory at H0-H3, not new
  stability work.

Primary counted generators to test first:

- M-QD-01;
- M-TC-01;
- M-PE-01;
- M-OI-01.

Merged post-FINAL bridges may be used, but only from canonical main.

## H0 deliverables

Create:

    docs/compression/hierarchy/HIERARCHY_INVENTORY.md
    docs/compression/hierarchy/HIERARCHY_GENERATOR_MATRIX.json

The inventory must distinguish at least:

- predictive/refinement hierarchy;
- resolution/realization hierarchy;
- parent/composition hierarchy;
- historical continuation;
- value/evaluation hierarchy;
- selection/reproduction hierarchy;
- long-run hierarchy.

Do not silently identify any two of these.

## H1 deliverable

For every inventory row, classify the strongest verified route as one of:

    COUNTED_GENERATOR_DERIVED
    MERGED_BRIDGE_DERIVED
    RETAINED_ADAPTER
    RETAINED_BOUNDARY
    RESIDUAL_OPEN

Each non-open route must cite exact Lean theorem surfaces or frozen P-ID
evidence.

## H2 deliverable

Audit parent formation separately from coarse-graining.

The working pressure test is:

\[
\text{children + interface}
\not\equiv
\text{mere quotient}.
\]

Explicitly test whether P-COMP obligations involving conditional path
irreducibility, parent predictive information, child-carrier realization, and
child-fidelity windows can be reconstructed from the current architecture.

## H3 deliverable

Build the smallest useful no-go/separation surface before proposing a new
positive hierarchy primitive.

Minimum targets:

1. quotient does not imply parent-object certificate;
2. parent object does not imply selection unit;
3. parent object does not determine a unique objective.

Additional separation results are welcome only when they close a concrete
false-unification route found by H0-H2.

## Explicitly deferred

Until the cross-track integration gate opens, Track H must not start a new
theorem family for:

- stationary-law perturbation stability;
- GOA tracking under model change;
- recurrent merge/split stability;
- residual-inverse stationary tracking;
- spectral derivation of stationary-branch isolation constants.

Those are owned by Track S.

## Promotion rule

No H0-H3 result changes the counted generator core.

Any later candidate primitive must undergo the normal Compression Mission
promotion, deletion/nonredundancy, CI, exact-head review, ledger, and
re-finalization lifecycle.
