# A 独立早期方法意见：SQLite 事务合同与公平比较

日期：2026-11-13。状态：**独立设计建议，尚未预注册，未运行认证，未读取 B/C 本阶段意见。** 当前 main 的固定源由主审刷新；已读上一轮交付的 NEXT_STAGE_EXECUTION_PROMPT 及 C7 两份文件，仅作为已核历史入口，待与现行字节重绑定。

## 1. 应检验的有限主张

建议主张是：在固定版本、rollback DELETE 配置、有限工作负载和明确故障类中，一个消费实际请求历史、结构检查和事务效果的有限预算判定器，能正确判定当前数据库是否符合**已确认历史及未确认事务的允许结果集合**，并与同信息、同预算的标准事务核对策略作比较。

“正确”不预设候选有增益；全情形规则等价可以是主要结论。不能只登记“没有错误 ACCEPT”，因为全部返回 UNRESOLVED 也会满足。须同时登记健康／已确认正常恢复的非空可决定集合，要求足够预算时确实给出结论；旧合法备份丢失已确认事务的负对照须被拒绝。

## 2. 三种不同的对象与三类确认状态

结构合法、当前业务状态、外部已确认历史分别保护。进程 PID 和数据库路径仅是来源线索；事务 ID 要与请求内容、数据库身份、运行代次和预期效果一起核对。

外部控制器的确认状态固定为：

- **ACK 已确认：** COMMIT 返回成功后，控制器实际收到带请求 ID 的成功确认；仅子进程发出或写入未收集 stdout 不能代替实际接收。
- **明确未提交：** 有成功回滚记录，或通过可复核的进程门控保证 COMMIT 尚未调用且其后不可能继续执行；不能仅凭没有 ACK、退出码或超时判定。
- **不确定：** 未满足前两项。提交可能已完成但确认尚未送达；不能按认证结果补写原历史标签。

设故障前状态为 S0、完整事务后状态为 S1，且无其他写入。三类允许当前结果分别是 {S1}、{S0}、{S0,S1}。S0、S1 必须包含完整事务效果和此前已确认历史，不只是一张 txn-ID 表。未知 ACK 下观察到一个允许状态，可以支持当前原子结果一致性；不能据此把原 ACK 事件改成已收到。

## 3. 两项最容易制造伪结果的机制

**自动恢复改变被观察对象。** SQLite 在读取前处理 hot journal；打开／查询可包含回滚、同步和 journal 删除。[O4] 目标进程退出后应先保存原数据库与相关 journal 的一致故障产物。每个策略使用同一产物的独立克隆，避免先跑者恢复后让后跑者免费使用。自动恢复属于双方共用的 SQLite 机制，不是候选发明；未测得底层 I/O 时，不把逻辑查询预算说成物理恢复预算。

**进程 kill 不等于断电。** 官方测试在特殊 VFS 中模拟未同步写的重排等效应。[O5] 当前 PRAGMA 文档也区分 DELETE 下 FULL 与 EXTRA 的断电耐久。[O3] 本阶段仅进程中断，不能从结果评价电源故障、内核故障、磁盘缓存或 WAL 的一般可靠性。

## 4. 公平对照与可反驳性

强标准方法应读取与候选相同的请求历史、实际效果、完整性结果及成本，采用通常的事务一致性／幂等请求核对和保守拒绝。仅“能打开且 integrity_check=ok”是有用弱对照，不能充当唯一竞争者。

必要反驳例包括：已确认请求缺失但候选仍 ACCEPT；事务只落一部分却被 ACCEPT；配置读回不符仍被计作目标条件；预算未足却声称已检查完；相同故障产物被两策略按不同信息或免费恢复先后次序处理。若双方同信息下逐情形相同，则应结案为等价／无额外决策增益。

旧合法备份必须是干净关闭的早期数据库副本。将它恢复到隔离副本可证明结构检查不蕴含已确认历史保留；这是**外部旧版替换**，不能记成 SQLite 进程崩溃导致丢失。

## 5. 最多三项 Core 原则的候选用法

1. 任务相对的观察与不可识别边界：结构正常不决定历史是否完整。
2. 允许动作与资源约束：打开自动恢复、查询、重试和恢复写入分别声明；不足即不认证。
3. 共同来源和身份角色分开：进程、文件、事务和业务历史的记录不能互相替代。

这些是待填精确源映射的使用方向，**尚不宣称已实例化某个 Lean 端点**。不强行消费人口增长、共同二维、GOD/GOA、生物自维持或 C2—C6 全套端口。

## 6. 已直接核读的官方来源

- [O1 Transaction](https://www.sqlite.org/lang_transaction.html)：§2.3 与 §3，COMMIT 的 SQLITE_BUSY 不等于回滚；事务错误后的状态须查明。
- [O2 Atomic Commit](https://www.sqlite.org/atomiccommit.html)：引言明确该页仅覆盖 rollback 机制；硬件前提与原子提交描述。
- [O3 PRAGMA](https://www.sqlite.org/pragma.html)：开头未知 pragma 可被忽略；integrity_check 的结构范围；journal_mode 读回；synchronous 的 FULL／EXTRA 差别。
- [O4 Locking v3](https://www.sqlite.org/lockingv3.html)：§4.1，读取前的 hot journal 自动处理。
- [O5 SQLite testing](https://www.sqlite.org/testing.html)：§3.3 的特殊 VFS 故障模拟。
- [O6 Isolation](https://www.sqlite.org/isolation.html)：独立连接的可见性、单写者与 rollback／WAL 机制区别。
