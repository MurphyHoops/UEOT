## 3. 事务真值、ACK 与 oracle

客户知识至少分三类：收到提交成功 ACK；协议已证明未提交/回滚；提交结果未知。未知不能默认为回滚，也不能因数据库恰好保留写入就倒填“客户曾确认”。在固定协议下，未知事务的允许结果集合可包含完整前态或完整后态；部分写入另按原子性判定。只有在协议明确额外承诺时，才可要求所有未 ACK 事务都不出现。

实验私有钩子若记录 COMMIT 已返回，但业务 ACK 尚未发出，控制器与客户的知识不同。私有阶段信息可以验证故障位置，不能未经登记传给候选或强基线。允许的业务查询可以解析未知；双方必须有同样权限和费用。超时、SQLite 错误或驱动异常应连同事务状态解释，不能由异常字符串直接断言整个事务回滚。

oracle 至少保留请求 ID、请求内容/版本、顺序与实际收到的 ACK。目标数据库不能同时充当关于自己的唯一业务真值来源。oracle 在故障域外是实验前提，不是本研究证明的无故障事实。外部账本一旦也故障，按协议标证据缺失，不能把其遗漏算作数据库丢失。

SQLite 首次访问可能自动重放 hot journal。应在故障进程终止后、任何检查之前，保留完整状态，包括数据库和该模式必需的 sidecar，再给各策略等价的独立副本。不能先让 oracle、弱基线或强基线打开并修复原件，再把已修复文件交给候选。若为了节省重复运行而共享同一次恢复后的观察，结论应限于诊断决策比较，不能据此宣称候选恢复算法更好。不得把遗漏 journal 的文件复制误称完整故障快照。

## 4. 故障达成与最小反例

受控未提交中断应由子进程明确进入事务、完成预登记写入并握手、停在 COMMIT 之前，然后父进程实际终止；边界场景需区分提交前、提交返回后/业务 ACK 前、已 ACK。只靠 sleep 或外层命名不是故障证据。未杀到、子进程已退出或握手超时均保留实际记录；只按预登记规则重分类或记 INTERVENTION_UNRESOLVED。

| 对照 | 合法构造 | 推翻的错误桥接 |
|---|---|---|
| N1 旧而合法的副本 | 关闭的隔离旧备份具有正常结构，但独立 ACK 账本已有后续义务 | integrity_check 正常就等于业务历史有效 |
| N2 ACK 不确定 | 提交结果与 ACK 接收分离，协议允许前/后完整状态 | 没收到 ACK 就一定没有提交 |
| N3 观察别名 | 两个业务真值不同的状态，在全部允许的弱观察下相同；固定结构、计数等可见量 | 弱观察足够识别业务身份；也检测路径/故障标签泄漏 |
| N4 资源不足 | 在下一个付费观察之前预算已不足 | 未付足代价却声称完成全量判断 |
| N5 身份分离 | 新 PID 保持业务承诺；旧文件结构正常却失去已确认内容 | 进程、inode、rowid 或结构正常就是业务同一性 |

还需正常提交、未提交中断恢复到允许前态，以及充分信息/预算能明确判断的正例，防止所有场景只给不确定。N1 是外部旧备份替换，并不是 SQLite 自身崩溃 bug。SIGKILL 只终止进程，不等于断电、内核崩溃、写重排或介质损坏。不能预先要求 synchronous=OFF 在进程终止后必然丢失数据；那是错误的故障桥。

不必为了数量重复所有负对照；在最小有限协议内覆盖会改变主结论的边界即可。

## 5. 同信息基线、预算和样本

策略输入必须由明确接口限定，不得含 fault=stale、oracle verdict 或携带答案的路径/运行编号。候选如果多看了一份业务账本，其相对弱基线增益首先属于信息增益；主比较的标准强基线必须也能看到该账本。强基线应从登记的可复核策略族选取，不能宣称对全部算法全局最强。

UEOT 不自动给出唯一 SQLite 算法。必须先给具体候选规则。如果候选和强基线在每个输入上执行同一规则，可证明或解释等价，合并无辨别力的重复计算；不能为制造优势故意削弱标准方法。平局后也不能改称未测量的认知优势已被证实。

必须明确资源是逻辑工作、应用字节还是硬件实测。仅“一 SQL 一单位”不能代表有界扫描；若只研究有限动作个数，应明确更弱主张且不掩盖实际工作。VM 指令计数、应用读写量、返回行数等是不同代理；不要换算成磁盘真实 I/O。记录首次打开与自动恢复的墙钟及可观测成本；无法精确归因时，限定预算为恢复后的诊断预算，并把恢复成本排除写入合同。中断回调存在粒度，应说明可超额上界，记录中断后的状态。

采样单位是重置后的运行或事先登记的场景，而非同一连接的多个查询。所有策略使用同一重置/缓存/顺序规则。至少一个工作负载或历史组合未用于校准；有限场景枚举不外推现实故障概率。若墙钟仅诊断记录且未控制顺序与缓存，不给速度优势结论。固定尝试数和停止规则，禁止追加直到出现胜例。
