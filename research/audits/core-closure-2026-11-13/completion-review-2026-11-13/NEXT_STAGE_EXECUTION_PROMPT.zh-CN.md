## 五、子智能体 B：实际实现、基线和运行负责人

在隔离目录完成可执行驱动，原则如下：

### 5.1 目标和独立裁判

- 启动真实 SQLite 子进程，在新建数据库执行带唯一 txn-ID 的有限事务。
- 父控制器保留请求内容和实际收到的提交成功确认。裁判记录独立于被故障影响的目标文件；它是信任前提，不能隐去。
- 区分已确认提交、明确未提交、提交状态不确定三类。子进程可能在提交完成而 ACK 尚未送达时被终止，此时根据协议给允许结果集合或标 UNRESOLVED；不得事后按喜欢的结果补标签。
- integrity_check 返回正常仅检查相应结构性质。必须另外检查独立事务记录、业务查询、历史版本或规范摘要；不能由结构正常推出业务数据无丢失。
- oracle 只用于最终判读。若策略消费其摘要，标准基线必须获得同样摘要、同样时机并承担同样费用。

### 5.2 故障与负对照

只对本任务独占的测试进程和测试文件干预，至少区分：

- 明确未提交事务期间的受控进程终止；
- 提交确认边界附近的受控进程终止，按实际 ACK 状态分类；
- 在封闭测试副本上恢复一个较旧但结构合法的备份，作为业务历史/身份负对照；
- 无故障正常运行和预算不足的边界情形。

进程 SIGKILL 不等同断电、内核崩溃、磁盘控制器重排或硬件损坏。任意外部文件误写、旧备份覆盖与合法崩溃恢复是不同干预，不能混为 SQLite 自身的 crash bug。

首轮不做真实断电、卸载用户卷或系统级故障。若要研究未同步写重排，应另给 VFS 等故障模型及其适用性证据，明确仍是受控模拟。已有 SQLite 与 CrashMonkey 方法须准确归属。

### 5.3 具体策略和公平基线

Core 并不唯一给出 SQLite 的检查/恢复算法。必须先把“由 UEOT 合同启发的应用策略”写成可执行规则，再评价它：

- 弱诊断基线：能打开数据库且结构检查正常。仅用于显示语义边界。
- 强标准基线：获得相同事务摘要、查询能力、历史、预算与调参机会的常规完整性/历史核对和保守恢复策略；从事先登记、可复核的现成方法或策略族中选择并说明理由，不声称对全部算法全局最强。
- 候选策略：在相同输入和动作权限下，显式消费选定 UEOT 合同的策略。
- 至少一个有意义消融：例如删除业务身份约束或逐前缀资源核算；明确这是消融，不把信息更少的版本当唯一强基线。

若两种策略实际等价，先给规则对应和等价理由；可以合并无区分能力的重复运行。不能靠新术语或人为削弱标准方法制造优势。即使有增益，首先归于具体策略和信息使用，不能自动归于一条新的 Core 普遍定理。

### 5.4 资源与测量

分别记录具有实际含义的成本，如查询扫描工作、应用文件读写字节、恢复写入、重启次数与墙钟耗时。不得用“一条 SQL = 一单位”掩盖无界全表扫描。

选择能够可靠观测或保守上界控制的有限预算单位；说明其是逻辑工作量、应用 I/O 还是硬件实测。对中断粒度、测量误差和未观测开销给界，无法给界时不认证严格物理资源保证。所有策略使用同一测量和收费规则。

B 产物：隔离 runner、明确版本/配置、原始事件日志、完整失败记录、基线/候选/消融结果、可独立重放命令和 EXECUTION_REPORT.md。

不得修改 SQLite 实现来使候选通过；不得把生成的结果标签作为测量结果。

## 七、必须完成的阶段顺序

### 阶段 0：恢复与选题

完成当前现场核验，读已有 C7 成果，固定独立目标系统、合理范围和许可证。确认任务不与其他活跃工作冲突。只有确实不能运行 SQLite 或不能取得必要观察时才选择替代系统，并说明同样的独立性和可检验性条件。

### 阶段 1：小规模校准与预注册

校准仅用于确认驱动、配置、日志与成本单位可用，数据与认证数据完全分开。不超过必要的小规模尝试；不得用认证结果反向确定阈值。

冻结：

- 一项主要应用主张与一个主要结局；定量增益主张给出最小实用差异，精确等价或证书主张给出逻辑判准，不强造效应量；
- fault/config/candidate 的有限集合、种子/运行次序和重置规则；
- 校准/认证/留出划分，缺失与 ACK 不确定的处置；
- 强基线、调参预算、消融及独立 oracle；
- 样本量理由和停止条件；
- 各类支持/拒绝/无增益/无法判定的判准。

确定性有限场景可枚举时，报告所枚举集合；随机场景的置信区间必须对应实际抽样单位，不能把同一未重置轨迹的查询当 iid。配置扫描与多重比较要预先说明。

将预注册保存成独立 commit，并在认证前固定 SHA。若以后改协议，保留旧结果，另起明确的新版本，不能把失败改成“从未正式运行”。

### 阶段 2：实际运行

完成全部登记运行。观察每次故障是否真的发生在声明边界；未达成的干预记录为执行问题。保留原始输入、输出、时序、配置、退出码、哈希、费用、超时和异常。

至少包含一个未用于校准的工作负载/历史状态组合，并限制外推。不能将同一个构造示例重复命名为多个独立应用。

### 阶段 3：独立复核与交叉质询

- A 质询 B：实际测量是否对应所声称的身份、信息和恢复？
- B 质询 A：哲学/数学解释是否超出实际数据和可执行策略？
- C 同时质询 A、B：共同假设、数据泄漏、弱基线和缺失案例是否导致伪增益？
- 主审独立处理分歧，记录双方证据、可复核位置、最终判断与剩余不确定。

只修复影响结果解释的真实问题；充分验证后停止扩展测试。

### 阶段 4：有限论文与正式采用

形成一份可独立阅读的研究稿：问题、先行工作、合同映射、方法、预注册偏离、所有结果、强基线、消融、反例、局限和可复现入口。

该稿是待外部评议材料，不宣称已经得到外部人类认可。准备评审问题即可，不自行给他人发送邮件/消息，不冒名邀请或声称有人接受。

在独立研究目录提交结果，正常审查、合并、回读准确 main 与内容；清理本轮已合并的工作分支，保留其他人的分支/工作树。更新当前导航时明确状态，不能因一次工程试验将全局自然经验 UNVERIFIED 改为已验证。

## 八、验收与停止规则

阶段验收必须同时满足：

1. 原 B 审计有限整改与 D3 未因旧标签或无差额重复被重开，历史记录没有被重写；真正的新反证按现行规则另案处理。
2. 已选独立目标，实际版本、配置、数据来源与源映射可核。
3. 预注册先于认证，协议变化及失败完整保留。
4. 强基线与候选同信息、同动作、同资源；策略是否等价已分析。
5. 真实过程运行，独立 oracle、阴性/边界对照与留出结果齐全。
6. C 的独立计算和分离重现完成，主审处理重大争议。
7. 结果明确归入下列一种或组合：有限支持；与标准方法等价/无额外增益；应用桥被拒绝；证据不足/不可识别；执行未完成。
8. 报告说明具体得到与失去的理论能力，所有公开声称不超出证据。
9. 源、原始证据、研究稿和后继入口完成正常归档/采用，未发生的动作不记完成。

负结果、等价结果和有实质依据的不可识别结果可以完成研究阶段。执行未完成必须清楚标明；不能靠改名为“范围完成”填补缺失数据。

Core 重开沿用现行 CURRENT 与范围决议：满足现行全部假设的真正反例、必要定义或类型冲突、实际消费者无法履行已承诺接口、影响相关证明的执行失败或证据错配，都应定位并提出精确议题；先区分源错误、环境问题和应用适配失败。重大公理和定义修改另行审议，不在本阶段直接覆盖定本。
