## 5. 下一阶段的一个具体研究目标：SQLite 业务承诺与恢复边界

### 5.1 唯一主问题

**在固定 SQLite 实现、明确故障机制、有限观察和恢复预算下，UEOT 的任务/身份/资源合同能否导出一个可执行应用策略，较同信息、同预算的标准诊断恢复策略获得可复现的业务承诺分类或恢复增益？若没有增益，它是否只是把既有条件更清楚地组织出来？**

这是新选的应用研究，不是修补 Core。必须接受零增益、同策略、观察不足、应用桥被否定等结果。SQLite 本来不是由 UEOT 为了验证自己构造的理论实例；但是我们新建的试验工作负载仍是人工实验，不能因此宣称自然系统普适性已证。

现有 C7 先导试验已经采用独立 OS worker 的多数服务、终止/替换和一 worker 弱基线；重复这个程序不能称新外部验证。新的 SQLite 目标应固定外部实现、先写需求和事务语义，再做 Core 映射。现 C7 外部模板仍是 DESIGN ONLY；新的任务书不是新数据。【C7 文档；E1-S】

### 5.2 为什么不能预设增益

Core 本身没有唯一指定一个 SQLite 检查/恢复算法。研究必须在观测认证数据前给出具体规则：读什么、何时停止、预算如何用、何时恢复、何时报告不确定。若“UEOT 策略”和标准策略在可观察历史上给相同行动，它们就是相同策略；换语言不产生预测增益。

若有增益，首先归于这个明确的应用策略、接口约束或信息使用；不能自动上升为 Core 一般数学新颖性。若只比较 integrity_check 与一套获得业务账本的强策略，优势可能完全来自额外信息。因此必须同时给弱基线和预注册可复核策略族中的强公平基线，并把主结论落在后者；不声称已比较所有可能算法。

### 5.3 试验范围与可证伪预测

首先固定一种日志机制和同步配置，建议首阶段只取 rollback 模式；必须查询读回实际生效的配置，不能凭设置命令退出 0。若另取 WAL，应另写相应机制合同，不能把 rollback 原子提交说明直接移植为同一证明。SQLite 官方说明明确区分两种实现机制；未知 PRAGMA 可能被静默忽略。【L2、L3；E1-L】

| 预测 / 负对照 | 如何使它可证伪 | 何种结论合法 |
|---|---|---|
| 正常完整事务和未提交中止 | 两个或多个互相关联写入；中途进程终止后重新打开，检查全有/全无和业务不变量 | 在已注册进程故障与配置下的局部原子性观察；不是新原子提交原理 |
| 已收到成功提交 ACK 的事务 | 独立控制器保存 txn-ID/内容/ACK；重启后逐笔查独立期望 | 已确认提交的任务记录是否保留；具体失败需先归因故障与oracle |
| 提交边界但未收到 ACK | 故意在提交返回与 ACK 送达之间留下竞争窗口 | 必须容许“已提交或未提交”的结果集合，不能把未知当损失或成功 |
| 结构完整但业务记录过期 | 在关闭后的隔离副本做受控旧备份恢复或外部错误写入，保留该干预记录 | integrity_check 可能仍通过而业务承诺失败；这是任务观察边界，不是 SQLite crash bug |
| 信息被剥离 | 把原业务账本/关键查询从两种方法同时移除 | 如果两世界在剩余观测下相同，应输出不确定；不得凭标签猜身份 |
| 资源不足 | 两种方法共享同一查询/读字节/写入/重启预算 | 合法行为是停止或不确定；预算外恢复不能记为成功 |
| 强标准策略 | 获得与 UEOT 策略完全相同的可用观测和动作；小有限策略族可穷举比较 | 允许性能完全相同，归类“无额外决策能力”；不能刻意保留弱对手 |

**不预注册“关闭同步后 SIGKILL 必丢数据”作为负对照。**进程死亡不等于断电；缓存与系统继续运行可使这类错误预测既不稳定也不对应目标故障。SQLite 官方 crash 测试使用特别 VFS 模拟未同步写重排/损坏；简单 kill 不复制这一机制。【L1；E1-L】

### 5.4 独立 oracle 与防止证据循环

oracle 由父控制器/独立日志建立，记录请求、事务标识、成功 ACK、失败和未知边界，不能直接以待检数据库自身输出充当全部真值。至少区分：

1. 期望事务已确认提交；
2. 已确认未提交/已回滚；
3. 结果尚未知，允许的状态集合明确。

认证评分时使用完整 oracle；策略运行时只获得预注册的部分。若策略也读取 oracle 的任何摘要，标准基线必须同样可读且计算相同成本。ACK 不确定不必永久不可判定：可通过预注册、双方同权且计费的允许查询解析，不能事后借完整 oracle 填标签。业务内容、记录身份和结构完整性须分别判定。SQLite 的 integrity_check 检查低层结构、索引及特定约束；它不独自表达本试验的外部承诺语义。【L3；E1-L；最后一句为明确推论】

所有随机种子、故障点、超时、重启、缺失日志和不确定样本均保存。干预未实际成功时属于 EXECUTION/INTERVENTION_UNRESOLVED，不能按预期故障标签评分。将数据库关闭后的旧副本替换归为明确的外部替换机制，不和运行中事务崩溃混算。

### 5.5 预算、基线与真正的结果

预算不能只数 SQL 条数，因为一条查询可无界扫描。至少分别登记观察调用数、实际可获取的读成本代理、写入/恢复次数、进程重启次数；主结果与测量局限一并给出。时间可作诊断，但不可通过未校准时钟或后台噪声制造优胜。两方的发现数据、预训练/规则调优和认证预算相同。

主要端点应预先确定为任务成功/失败/不确定的完整混淆表、违规预算数、恢复后的实际业务承诺和成本。若提出概率效力或泛化率，必须另说明抽样设计与依赖；有限固定场景的全量结果不能冒充现实故障率。

研究的有价值结果包括：

- 多种观察在结构正确与业务承诺之间的精确分界；
- 在同等信息下发现某具体策略减少无效检查或错误恢复；
- 标准策略已达到同样能力，UEOT 贡献限于合同可追踪；
- 某桥接或身份解释被真实干预否定，收窄应用模型；
- 可用信息不足，报告 UNIDENTIFIED 而非人为制造唯一对象。

C 主动指出并由 B 收入的边界是：单矩阵
\[
J=\begin{pmatrix}1&1\\0&1\end{pmatrix},

J^n=\begin{pmatrix}1&n\\0&1\end{pmatrix}
