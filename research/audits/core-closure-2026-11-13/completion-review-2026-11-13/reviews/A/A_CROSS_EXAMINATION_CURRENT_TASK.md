### 3.1 三项任务谓词应分开

结构完整、外部 ACK 业务承诺、记录身份可以作为不同任务谓词。这符合当前 Core 按来源、观察、行动和任务确定合同的用法。记录身份应声明请求来源、标识、内容、版本与允许变化关系，不能仅用数据库键或相同字节宣称现实客体的数值同一。

应固定一个应用合同：版本／配置、允许故障、事件历史、可读观察、恢复动作、成本以及外部承诺。若引用某一 Core 定理，仍须给出它所需的状态与机制映射并验证精确前提；仅用 UEOT 术语组织 SQLite 文档还不构成形式实例定理。

业务承诺是研究者和应用设置的评价，不是数据库“内在唯一目的”。这个事实不使合同任意：给定已声明承诺，它可以产生明确的对错与未知结果。

### 3.2 ACK 三值 oracle

接受 C 区分已确认提交、已确认未提交／回滚、未知边界的设计。没有 ACK 或发生超时，不自动成为已回滚的证据。Oracle 的控制器／日志须在所注入故障域外，或明确记录其自身故障责任，否则“独立 oracle”只是名称。

未知状态可以由预注册允许的后续查询解除，但若策略有权读取 oracle 摘要，公平基线须获得相同信息、付相同成本。评分不能将未知样本删除后只报告已确认成功率。这些是实验设计责任，不是新 Core 公理。

### 3.3 零增益何时仍可成功结案

若预注册问题是“是否存在相对强公平基线的决策／恢复增益”，充分证据支持无增益，是阶段成功的合法结果。它否定的是本次策略优势，不否定条件 Core 定理。

但不得在平局后把成功指标改成“提升理解”，并宣称一种没有测量的认知优势。可如实说合同和轨迹可追踪、没有增加决策能力；若要量化减少错误或提高理解，应另设相应观察，不得事后挪用“结构组织”当性能优胜。

### 6.3 NP 比较中真正重要的解释限度

B §6.7 不仅声明一般先行存在，还将它与具体源责任分开：一般非负 product-family 的 JSR、最大单矩阵谱半径和共同正势下确界相等；最优处严格正势是否达到，以及它怎样支撑实际人口的统一全时界，须另作检查。A 可直接复核其中 Jordan 矩阵例的简短推导：`J^n` 的上三角项为 `n`，因此谱增长率 1 不保证存在有限常数 C 使全部终期量小于等于 `C·1^n`，也不存在所要求的严格正共同势。这一反例防止把“增长指数相同”偷换成“所有时刻的实际数量保证相同”。

本例中达到最优处的正势、源内行与全允许策略期望桥，可以是具体数学／形式化成果；使用成熟正向量方法，不损害其正确性，也不自动证明其全球首创。它们同样没有使程序继承、模型亲本记录或外部供给变成组织约束闭包的普遍充分条件。因此 B 的最终稿与 A 首审对 Montévil／Mossio 等先行理论的非蕴含判断相容，无须新增一个把这些不同理论强行等同的 Core 桥。
